> 대상은 `seongwoo-todo/assets/generated/{a,b,c}-group/`.
> 기준 문서는 [`DESIGN-DIRECTION.md`](./DESIGN-DIRECTION.md) · [`DESIGN-PROMPTS.md`](./DESIGN-PROMPTS.md).

지금 **20개 시트 중 17개가 인게임에 적용돼 있습니다.** 아래는 남은 셋과, 적용은 됐지만

## 0. 먼저 알아야 할 규칙 두 가지

### 규칙 A — 셀은 "1타일을 2배로 그린 크기"다

이 게임의 1타일은 화면에서 **32 × 32 px**입니다. 에셋은 2배로 그려 **64 × 64 px 셀**에
담고, 로더가 불러온 직후 **한 번** 절반으로 구워 32×32로 씁니다.

```
64×64 셀  ──(로드 시 1회 축소)──▶  32×32 화면
```

지금 20개 중 18개가 이 규칙을 지키고 있습니다. **B4·B5만 세로가 32**여서 어긋납니다.

### 규칙 B — "2배로 그린다"는 픽셀을 2×2 블록으로 찍는다는 뜻이다

가장 자주 어긋나는 부분입니다. 64px 셀 안에 **1px 단위의 세밀한 무늬**를 그리면,
절반으로 줄일 때 그 절반이 그대로 버려집니다.

```
올바름:  32×32 로 그린 뒤 → 니어리스트 이웃으로 2배 확대 → 64×64 로 저장
         (한 논리 픽셀 = 2×2 블록. 축소해도 원본이 그대로 복원된다)

잘못됨:  처음부터 64×64 캔버스에 1px 붓으로 세밀하게 그림
         (축소하면 세로·가로 한 줄씩 통째로 사라진다)
```

아래 표의 **"2배 블록 일치율"** 이 이걸 측정한 값입니다. **85% 이상이면 안전**하고,
낮을수록 축소할 때 무늬가 깨집니다.

## 1. 반드시 다시 만들어야 — 지금 게임에 못 넣고 있음

### ~~1-1. `b-group/B4-gate.png`~~ — ✅ 2026-08-25 해결 (커밋 `fb31528`)

256×64 로 재출력돼 인게임 적용 완료. 열림·닫힘 4단계가 채널 상태와 맞물려 돈다.

<details><summary>당시 문제 (기록용)</summary>

#### 원래 내용 — 세로가 절반

| | |
|---|---|
| 현재 | **256 × 32** (4열 × 1행, 셀 64 × 32) |
| 필요 | **256 × 64** (4열 × 1행, 셀 **64 × 64**) |
| 왜 | 이 게임의 게이트는 15개 스테이지 **전부 1×1 타일 = 32×32 px**. 지금 셀은 축소하면 32×16이라 문 높이의 절반만 덮음 |

**가로는 그대로, 세로만 32 → 64로.** 프레임 수(4개)와 "양옆에서 가운데로 닫히는" 연출은
그대로 유지하면 됩니다.

프롬프트에서 고칠 곳은 한 줄입니다.

```diff
- SHEET: 1 row x 4 columns, each cell exactly 64x32 (a 2-tile-wide doorway at 2x)
+ SHEET: 1 row x 4 columns, each cell exactly 64x64 (a 1-tile doorway at 2x)
```

프레임 의미는 그대로입니다 — 1번 완전 열림(문틀만 + 옅은 초록 바닥), 2·3번 닫히는 중,
4번 완전 닫힘.

</details>

### ~~1-2. `b-group/B5-exit.png`~~ — ⚠️ 크기는 해결, **이음매는 미해결**

256×64 로 재출력돼 적용 완료. 다만 셀마다 사방에 완결된 문틀이 있어서, 2타일 출구
(스테이지 1·5·7·12)에서 좌우로 붙이면 **가운데에 문틀이 두 겹으로 겹쳐 보인다.**
문 한 짝이 아니라 두 짝으로 읽힌다.

고치려면 셀의 **왼쪽 끝과 오른쪽 끝 세로 문틀을 절반씩만** 그려서, 두 장을 붙였을 때
가운데에 온전한 기둥 하나가 되도록 해야 한다. 급하지는 않다 — 15개 중 4개 스테이지에
해당하고, 지금도 이중문으로는 읽힌다.

<details><summary>당시 문제 (기록용)</summary>

#### 원래 내용 — 같은 문제 + 이음매 조건

| | |
|---|---|
| 현재 | **256 × 32** (4열 × 1행, 셀 64 × 32) |
| 필요 | **256 × 64** (4열 × 1행, 셀 **64 × 64**) |
| 왜 | 탈출구가 **1×1인 스테이지가 11개, 2×1인 스테이지가 4개**(1·5·7·12번). 1타일 셀로 만들고 2타일에서는 좌우로 이어 붙이는 방식이 가장 단순함 |

**추가 조건 하나**: 좌우로 이어 붙이므로 **셀의 왼쪽 끝과 오른쪽 끝이 서로 맞물려야**
합니다. 문틀 두께와 명암이 양 끝에서 같아야 이음매가 안 보입니다.

```
2×1 탈출구:  [ 셀 ][ 셀 ]   ← 같은 그림 두 장을 가로로 붙임
             └──── 이 경계에서 선이 끊기면 안 됨
```

프레임 의미는 그대로입니다 — 1·2번 SEALED(먼지 반짝임만), 3·4번 OPEN(초록 테두리 흐름).

</details>

## 2. 다시 뽑아야 — 축소할 때 무늬가 깨짐

크기는 맞지만 **규칙 B**를 어겨서, 절반으로 구울 때 그린 것의 절반이 버려집니다.
**그림을 다시 그릴 필요는 없고, 32px 논리 해상도로 정리한 뒤 2배 확대해 재출력**하면 됩니다.

| 파일 | 2배 블록 일치율 | 상태 |
|---|---:|---|
| `a-group/A3-grate.png` | **5.0%** | 심각 — 사실상 1배 그림. 격자 무늬가 한 줄 걸러 사라짐 |
| `b-group/B11-tileset.png` | **37.0%** | 심각 (아래 §3 도 함께 해결 필요) |
| `b-group/B7-pressure-plate.png` | **42.1%** | 나쁨 |
| `b-group/B10-crate.png` | **46.4%** | 나쁨 |
| `a-group/A4-laser-beam.png` | **70.8%** | 보통 (아래 §4 도 함께) |
| `b-group/B8-lever.png` | **71.7%** | 보통 |
| `b-group/B2-brute.png` | **72.6%** | 보통 |

참고로 잘 나온 것들은 이렇습니다 — **B3 코어 94.7% · A2 폭발 93.3% · A1 섬광탄 92.4% ·
B1 주인공 89.3%**. 이 넷과 같은 방식으로 출력하면 됩니다.

> **작업 방법**: 이미지 편집기에서 원본을 50%로 축소(니어리스트 이웃) → 무늬가 의도대로
> 남았는지 확인하고 다듬기 → 다시 200%로 확대(니어리스트 이웃) → 저장.
> 보간(bilinear/bicubic)을 쓰면 안 됩니다. 색이 섞여 팔레트가 늘어납니다.

## 3. 색 수정

### 3-1. `b-group/B11-tileset.png` — 바닥이 콘크리트가 아니라 **물때색**

가장 눈에 띄는 색 문제입니다. 12칸 중 바닥 계열 7칸의 대표색이 전부 `#3a3b26`인데,
이건 디자인 문서에서 **"벽 밑동 물때"** 로 지정된 색입니다. 바닥 기본색이 아닙니다.

| 셀 | 지금 | 있어야 할 색 |
|---|---|---|
| (0,0) 바닥 기본 | `#3a3b26` 물때 | **`#4b433a`** 콘크리트 |
| (0,2) 바닥 얼룩 | `#3a3b26` | **`#2b2622`** 얼룩 |
| (1,0) (1,1) 균열 | `#3a3b26` | **`#4b433a`** 바탕 + `#211d18` 이음새 |
| (1,2) 환기구 · (2,0) 배수구 | `#3a3b26` | **`#544b40`** 강철 |

지금 이대로 넣으면 **바닥 전체가 초록빛으로 돌아** 게임에 이미 구워져 있는 바닥

(0,1) 셀만 `#4b433a`로 맞게 칠해져 있으니, 그 칸의 색조를 나머지 바닥 칸에 맞추면 됩니다.

## 4. 반투명 가장자리

투명 배경 가장자리에 **알파가 0도 255도 아닌 픽셀**이 있으면, 어두운 배경 위에서 색이
번져 보입니다. 픽셀 아트에서는 알파를 0 또는 255로만 두는 게 안전합니다.

| 파일 | 반투명 픽셀 비중 |
|---|---:|
| `a-group/A4-laser-beam.png` | **11.1%** — 가장 심함 |
| `b-group/B2-brute.png` | 2.8% |
| `a-group/A2-flashbang-detonation.png` | 2.3% |
| `b-group/B2-watcher.png` | 2.1% |

빔은 원래 발광체라 반투명이 의도일 수 있지만, 11%는 과합니다. 이어 붙여 그리는 그림이라
가장자리 반투명이 **이음매마다 겹쳐 누적**됩니다. 빔 심지는 불투명으로, 번짐은 코드가
얹는 글로우에 맡기는 편이 낫습니다.

## 5. 형태 문제 — 다시 만들지 말고 **코드로 보완 중**

### `b-group/B7-pressure-plate.png` — "밟는 것"이라는 표시가 없음

시트는 **평범한 강철판**입니다(1번 올라옴 / 2번 눌림+초록 테두리). 그런데 심사에서
**세 명이 독립적으로 이 판을 "방 이름표"로 읽고** 첫 스테이지를 못 깼습니다. 게이트도
테두리 + 가운데 대문자 라벨이라 둘이 같은 표지판으로 보인 것이 원인이었습니다.

지금은 **코드가 아래로 꺾인 갈매기 표시와 미끄럼 방지 홈을 판 위에 계속 그려서** 막고
있습니다. 에셋만으로 해결하고 싶다면 1번(올라옴) 프레임에 다음 중 하나를 넣어 주세요.

- 판 위쪽 가운데를 향해 꺾인 **갈매기(∨)** — 지금 코드가 그리는 것과 같은 형태
- 발자국 아이콘
- 판 표면의 **수평 미끄럼 방지 홈** — 게이트의 비스듬한 위험 도색과 질감으로 구분됨

색은 바닥 위치 도색 `#8f7a2e`를 쓰면 됩니다(코드에서 `C_FLOOR_MARK`로 정의해 뒀습니다).
에셋에 들어가면 코드 쪽 표시는 제거하겠습니다.

## 6. C그룹 — 조치 완료, 참고만

원본이 장당 1.6~2.7MB(여섯 장 합계 **14.5MB**)라 그대로 실으면 첫 화면까지 그만큼을
받아야 했습니다. 캔버스가 960×600 고정이라 그 이상 해상도는 화면에 닿지도 않습니다.

**원본은 그대로 두고** 납품본을 따로 만들어 쓰고 있습니다.

```
c-group/*.png              원본 (1536×1024 · 1600×1000, 14.5MB) — 보관용
c-group/delivery/*.png     납품본 (960×640 · 960×600 그레이스케일, 2.0MB) — 런타임
```

재생성은 `bash scripts/derive-scenes.sh`. **새 C그룹 이미지를 추가하면 이 스크립트를
한 번 돌려야** 게임에 반영됩니다.

흑백 만화라 유채색 픽셀이 0.03%뿐이어서 그레이스케일 변환에 손실이 없었습니다.
