# I.MY.ME.MINE — 3분 제출 영상 콘티

## 영상 방향

**형식:** 몰입형 게임 트레일러 + 실제 플레이 증명 + 개발 검증 기록  
**총 길이:** 3분(180초)  
**화면 비율:** 16:9, 1920×1080 이상  
**권장 촬영:** 실제 게임 60fps 녹화, 최종 출력 30fps 또는 60fps  
**나레이션:** 20대 남성 주인공 1인칭  
**핵심 카피:** 실패한 내가, 다음의 나를 살린다.

영상은 발표자료처럼 기능을 나열하지 않는다. 처음 40초 동안 세계에 관객을 끌어들인 뒤, 실제 플레이만으로 규칙을 이해시키고, 후반부에 콘텐츠 규모와 Codex 활용을 짧게 증명한다.

전체 감정선은 다음 순서로 진행한다.

> 혼란 → 발견 → 이해 → 활용 → 압박 → 결심 → 탈출

# 구간별 콘티와 나레이션

- 처음에는 인물과 복도만 보이고, 형광등이 한 번 깜빡인 뒤 게임 제목이 나타난다.

### 사운드

## 0:06–0:38 — 카툰 인트로

### 화면

- 게임에 구현된 카툰 인트로를 실제 재생 속도보다 조금 빠르게 편집한다.
- 한 페이지를 통째로 오래 보여주지 말고, 칸 내부를 천천히 이동하며 디테일을 보여준다.
- 선반, 닫힌 문, 균열, 실루엣, 반복 실험의 흔적이 차례로 등장한다.
- 카툰 컷의 흰 여백이나 말풍선 영역에는 별도의 설명 문구를 추가하지 않는다.
- 컷 전환은 글리치보다 형광등 점멸과 필름 프레임 이동으로 처리한다.

### 나레이션

> “낯선 천장. 꺼질 듯한 형광등.”
>
> “여긴 어디지?”
>
> “기억나는 건 없다. 문은 잠겨 있고, 복도 끝에선 누군가 걷고 있었다.”
>
> “그런데 이상했다. 걸음도, 멈추는 순간도, 전부 나와 같았다.”
>
> “저건… 조금 전의 나다.”

### 연기 지시

- 처음부터 공포에 질린 목소리를 내지 않는다.
- 막 깨어난 사람처럼 호흡이 짧고, 주변을 확인하며 낮게 말한다.
- “여긴 어디지?” 뒤에는 약 1초간 빈 공간을 둔다.
- “조금 전의 나다”에서는 놀람보다 이해할 수 없는 상황을 받아들이는 느낌을 낸다.

### 사운드

- 형광등, 먼 기계음, 배수관의 물방울 소리를 사용한다.
- 복도 실루엣이 등장할 때 발소리를 화면보다 먼저 들려준다.
- 카툰 마지막 컷에서 발소리가 실제 게임 화면으로 이어지게 한다.

## 0:45–1:12 — 핵심 기능: 기록하고 남긴다

### 화면

Stage 1의 압력판과 문을 이용해 게임 규칙을 한 번에 설명한다.

1. 현재 플레이어가 닫힌 문으로 접근한다.
2. 발판을 밟자 문이 열린다.
3. 발판에서 내려오자 문이 다시 닫힌다.
4. 플레이어가 발판 위로 돌아온다.
5. `R`로 루프를 조기 확정한다.
6. 화면이 리셋된다.
7. 잔상이 이전 동선을 그대로 따라가 발판을 밟는다.
8. 현재 플레이어가 열린 문을 통과한다.

가능하면 한 장면 안에서 보여주고, 꼭 필요한 경우에만 첫 루프와 두 번째 루프를 좌우 분할 화면으로 2~3초 비교한다.

### 나레이션

> “혼자서는 저 문을 열 수 없다. 발판에서 내려오는 순간 다시 닫힌다.”
>
> “그래서 먼저 발판을 밟는다.”
>
> “그리고 여기서, 지금의 나를 확정한다.”
>
> “시간은 처음으로 돌아가지만, 방금 전의 나는 그대로 움직인다.”
>
> “이제 문이 열렸다.”

### 화면 문구

장면 하단에 한 단어씩만 사용한다.

```text
RECORD
COMMIT
REPLAY
ESCAPE
```

### 사운드

- 발판이 눌리는 금속음과 문이 열리는 소리를 크게 살린다.
- `R` 입력 시 저음 충격음 뒤에 0.2초 무음을 넣는다.
- 루프 재시작에는 과한 역재생 효과 대신 짧은 전기 차단음을 사용한다.
- 잔상 발소리는 현재 플레이어보다 약간 얇고 멀게 들리게 한다.

## 1:12–1:42 — 실제 플레이: 잔상으로 경비를 속인다

### 화면

Stage 5의 경비 유인 장면을 사용한다. 이 게임의 가장 강한 차별점이므로 충분한 시간 동안 원인과 결과를 모두 보여준다.

1. 현재 플레이어가 경비의 시야 때문에 통로를 지나지 못한다.
2. 첫 루프에서 반대편 복도를 `Shift`로 달린다.
3. 경비가 발소리를 듣고 조사하러 이동한다.
4. 다음 루프에서 잔상이 같은 순간에 달린다.
5. 경비가 잔상을 실제 플레이어처럼 추적한다.
6. 현재 플레이어가 비워진 통로를 통과한다.

경비가 왜 이동했는지 이해할 수 있도록 소음 링, 경비의 방향 전환, 추적 동선을 한 화면에 담는다.

### 나레이션

> “다음 방부터 경비가 나타난다.”
>
> “녀석은 잔상도 실제 사람처럼 보고, 그 발소리를 쫓는다.”
>
> “과거의 나를 반대편으로 뛰게 한다.”
>
> “경비가 따라간다.”
>
> “싸울 필요는 없다. 비워진 길로 빠져나가면 된다.”

### 화면 문구

```text
THE WORLD REACTS TO EVERY VERSION OF YOU.
```

### 편집 지시

- 잔상이 달리는 장면과 경비가 반응하는 장면을 빠르게 잘라 붙이지 않는다.
- 잔상의 발소리 → 경비의 고개 회전 → 경비 이동 → 현재 플레이어 통과가 한 인과관계로 보여야 한다.
- 이 장면은 3분 영상에서 가장 긴 실제 플레이 숏으로 유지한다.

## 1:42–2:05 — 장치와 플레이 방식 확장

### 화면

3. 주기 레이저 사이를 정해진 시각에 통과한다.

6. LISTEN 모드에서 마이크 음량 단계가 반응한다.
7. 이전 루프의 소리가 재생되고 경비가 그쪽으로 움직인다.

> “발판, 레버, CCTV, 레이저.”
>
> “방이 깊어질수록 한 번의 루프가 해야 할 일이 늘어난다.”
>
> “섬광탄으로 감시를 끊고, 전력을 돌리고, 정해진 순간을 통과한다.”
>
> “LISTEN 모드에서는 내가 낸 소리도 테이프에 남는다.”
>
> “기침 한 번도 다음 루프의 미끼가 된다.”

### 화면 문구

## 2:37–2:49 — Codex 활용 증명

### 화면

게임 분위기를 깨는 발표 슬라이드 대신, 연구시설의 기록 모니터처럼 편집한다. 단, 게임 속 설정과 실제 개발 기록은 혼동되지 않도록 상단에 `DEVELOPMENT LOG / CODEX`라고 명확히 표시한다.

1. Codex가 브라우저에서 게임을 플레이하는 장면
2. 심사 기준에 따른 문제 발견 기록
3. 수정 전후 동일 경로 비교
4. 전체 테스트 통과 화면

각 장면은 실제 기록만 사용한다. 구현하지 않은 기능이나 확인되지 않은 기여를 넣지 않는다.

### 나레이션

> “이 게임은 개발 과정도 반복해서 검증했다.”
>
> “Codex가 직접 플레이하고, 심사 기준으로 약점을 찾고,”
>
> “수정 뒤 같은 경로를 다시 확인했다.”

### 화면 문구

실제 최신 수치와 일치할 때만 노출한다.

```text
PLAY → EVALUATE → BUILD → VERIFY
420 TESTS · 105 SUITES · 0 FAILURES
```

테스트 수가 변경됐다면 영상 제작 당일 `npm test` 실측값으로 교체한다.

## 2:49–2:57 — 클라이맥스

### 화면

후반 스테이지에서 세 잔상과 현재 플레이어가 각자 다른 역할을 수행하는 장면을 사용한다.

- 첫 번째 잔상이 경비를 유인한다.
- 두 번째 잔상이 장치를 작동한다.
- 세 번째 잔상이 전력 또는 문을 유지한다.
- 현재 플레이어가 닫히기 직전의 마지막 문을 통과한다.
- 문이 닫히는 순간 화면이 검게 전환된다.

가능하면 하나의 연속 플레이로 촬영한다. 빠른 컷으로 기능을 감추지 않는다.

### 나레이션

> “마지막 문 앞에는, 지금까지 남긴 내가 모두 필요하다.”

### 사운드

- 음악을 최고조까지 올리되 발소리와 문 작동음은 들려야 한다.
- 플레이어가 문을 통과한 직후 음악과 환경음을 모두 끊는다.
- 마지막 문이 닫히는 금속음만 남긴다.

# 나레이션 연출 가이드

## 목소리

- 20대 남성
- 낮고 차분한 톤
- 광고 성우처럼 힘을 주지 않음
- 게임 속 주인공이 혼잣말하는 거리감
- 초반에는 상황을 파악하지 못한 짧은 호흡
- 핵심 규칙을 이해한 뒤부터 문장 속도가 조금 빨라짐
- 마지막 문장에서는 속도를 다시 낮추고 또렷하게 마무리

## 피해야 할 연기

- 공포 영화 예고편 같은 과장된 속삭임
- 모든 문장을 같은 무게로 읽는 방식
- 감탄사나 거친 숨소리 남발
- 기능 설명 구간에서 갑자기 발표자처럼 변하는 방식
- 영어 모드명을 과도하게 굴리는 발음

## 녹음

- 마이크와 입의 거리는 15~20cm
- 같은 원고를 감정 강도 70%와 50% 버전으로 두 번 녹음
- 노이즈 제거를 과하게 적용해 목소리가 금속성으로 변하지 않게 함
- 배경음과 섞였을 때 나레이션이 항상 3~5dB 앞에 있도록 조정

# 썸네일 구성

## 권장안

- `C2-title-key-visual.png`을 16:9로 확장하거나 안전하게 크롭한다.
- 현재 플레이어는 화면 중앙보다 약간 오른쪽에 둔다.
- 세 잔상은 뒤쪽으로 이어져 시간의 흐름이 보이게 한다.
- 출구와 빛은 진행 방향에 배치한다.
- 제목은 상단의 비어 있는 영역에 넣는다.
- 문구는 제목과 `FAIL NOW. ESCAPE LATER.`만 사용한다.
- OpenAI Game Builders 표기는 하단 모서리에 작게 배치한다.

## 피해야 할 구성

- 조작키와 HUD가 가득 보이는 스크린샷
- 작은 글자로 기능을 여러 개 나열한 썸네일
- 캐릭터보다 글자가 더 큰 구성
- 네온 색상을 추가해 기존 팔레트를 깨는 방식
- 실제 게임에서 볼 수 없는 장면을 합성하는 방식

영상의 첫 프레임과 썸네일을 같은 이미지로 사용하면 클릭 이후의 시각적 연결이 자연스럽다.

## 중요한 효과음

- 형광등 점등
- 금속 발판 눌림
- 게이트 개폐
- `R` 루프 확정
- 현재 플레이어와 잔상의 서로 다른 발소리
- 경비가 소리를 인식하는 순간
- 레이저 점멸
- 섬광탄 폭발
- 전력 채널 전환
- 마지막 문 폐쇄

게임에서 합성되는 실제 효과음을 우선 사용한다. 추가 사운드를 넣더라도 게임에서 들을 수 있는 소리가 묻히지 않도록 한다.

- 카툰 프레임 이동
- 루프 리셋

무관한 글리치, 화면 흔들림, VHS 노이즈를 장면마다 반복하지 않는다. 전환은 게임 안에서 실제로 일어나는 사건에 맞춘다.

# 자막 가이드

- 한국어 나레이션에는 영문 자막을 제공한다.
- 영문 자막은 화면 하단 안전 영역 안에 한 줄 또는 두 줄로 배치한다.
- 모바일 재생을 고려해 1080p 기준 최소 42~48px을 권장한다.
- 흰색 글자와 70~80% 검은 반투명 배경을 사용한다.
- 게임 HUD와 겹치면 상단으로 옮기되 장면마다 위치가 흔들리지 않도록 한다.
- 화면 문구와 자막이 동시에 길게 나오지 않게 한다.
- `I`, `MY`, `ME`, `MINE`, `Codex`는 번역하지 않는다.

- 잔상 때문에 경비가 이동했다는 인과관계가 보이는가

- 구현되지 않은 기능이 포함되지 않았는가

- PC와 모바일 플레이가 모두 보이는가

- 자막이 HUD를 가리지 않는가
- 기술 오류, 콘솔, 커서, 개발용 UI가 노출되지 않는가
