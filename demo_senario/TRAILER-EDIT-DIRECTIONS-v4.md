## 0. 【최우선】 플레이 영상 버벅임 — 원인 확정, 전면 재캡처 필요

**진단 결과 (2026-08-26 실측)**: 원본 캡처 파일의 컨테이너는 30fps지만
**실제 평균 프레임률이 9.07fps** (`ffprobe avg_frame_rate=136/15`).
ffmpeg의 macOS 화면 캡처(avfoundation)가 레티나 전체 해상도(2880×1800)에서
초당 9장 남짓밖에 못 건졌다 — 게임은 60fps로 돌았지만 녹화가 그걸 못 따라온 것.
배속·인코더 문제가 아니라 **캡처 단계의 문제**라, 편집으로는 못 고치고 재캡처가 답이다.

**해결 순서 (위에서부터 시도, 5초 테스트 캡처로 실효 fps 확인 후 채택)**:
1. **`screencapture -v -R<x,y,w,h> out.mov`** — macOS 내장 ScreenCaptureKit 기반이라
   효율이 훨씬 좋고, `-R`로 게임 캔버스 영역만 잡으면 픽셀 수가 1/3로 줄어 이중으로 유리.
   (종료는 프로세스에 SIGINT. 검증: `ffprobe avg_frame_rate`가 30/1 또는 60/1에 근접해야 통과)
2. 안 되면 avfoundation 유지 + **캡처 부하 축소**: 디스플레이 해상도를 낮추거나(1920×1200),
   `-framerate 60 -c:v h264_videotoolbox`로 재시도 후 실효 fps 재측정.
3. 그래도 안 되면 브라우저 창을 절반 크기로 줄여 캡처 픽셀 수를 줄인다(캔버스 크롭 좌표 재계산).

**기준**: 채택된 방식의 테스트 캡처에서 실효 fps ≥ 30 확인 전에는 본촬영 금지.

## 1. 【신규】 전 스테이지(15개) 플레이 촬영 → 골고루 배치

- 정답 테이프가 `tests/solvability.test.ts`에 **15개 스테이지 전부** 있으므로, 기존
  테이프 드라이버 파이프라인(dev 서버 + `window.__imm.stage(n)`/`queue(masks)`)으로
  스테이지별 클립을 전부 딴다. 파일명 `footage/s01.mp4` ~ `s15.mp4`.
- 촬영 규격: §0에서 채택한 캡처러, 실효 30fps 이상, 게임 캔버스 크롭, 커서 제거,
  각 클립은 리셋 프레임부터 ESCAPED까지.
- **배치 방침** — 같은 방만 반복해서 보이지 않게:
  - 기능 몽타주: 소음 바닥(6), 상자(3), 시간차 버튼(2), CCTV/WATCHER(7~8), 레이저(10),
    섬광탄(10), 전력(13~14) 등 **막별로 다른 방** 2~3초 컷을 최소 6종
  - 규모 소개(15 STAGES): 1막·2막·3막·4막 대표 방 4분할 — s02, s07, s11, s14 권장
  - 클라이맥스: s15의 **이동 구간**(§2)
- 촬영 순서 자동화: 스테이지당 "예약(2s) → 녹화 → 클리어 검증(outcome=CLEARED) →
  다음"을 반복하는 배치 스크립트로 한 번에. 사용자 화면 점유 약 10분 — 사전 고지 필수.
