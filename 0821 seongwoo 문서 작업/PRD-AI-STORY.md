# PRD — AI 스토리 시스템 「다음 배치(Next Batch)」

> **이 문서의 용도**: 막간 선택 → 사전 제작 스테이지 변형 → 자유 문장 파싱 →
> 개인화 결말 생성 → **이후 플레이어에게 이어지는 레거시**까지, AI 스토리 기능군의
> 기획을 확정하기 위한 결정용 문서다. **코드 작성 전 단계**이며, 이 문서가 승인되기
> 전에는 구현하지 않는다.
>
> **상태**: 제안(v2 — 심사위원 페르소나 리뷰 반영판). §11 미결 사항에 대한 팀 결정 대기.
> **주의**: OpenAI 게임 해커톤의 공식 심사 기준은 아직 공개 전이다(곧 GitHub 업데이트
> 예정). §9의 기준은 **가정**이며, 공식 기준 공개 시 §9만 다시 평가한다.
> (작성: 2026-08-21 · 상위 방향 문서: [`PRD.md`](../PRD.md) · 아이데이션 근거: [`AI-KICK-IDEAS.md`](../AI-KICK-IDEAS.md))

## 0. 한 장 요약

스테이지 사이 막간 만화에서 주인공이 **선택**한다. 선택은 (1) 미리 만들어 둔 스테이지
변형 중 하나를 고르고, (2) 결말 분기에 쌓인다. 선택지 일부는 **자유 문장 입력**이고,
GPT가 문장을 사전 정의 카테고리로 환원한다 — 즉 어떤 문장을 쓰든 도착지는 미리 만들어
검증해 둔 변형 중 하나다. 결말에서 GPT가 그 사람의 선택·문장·플레이 로그로 **개인화된
엔딩 서사**를 쓰고, 그 결과물의 일부가 **다음 플레이어의 세계에 남는다** — 이전 배치가
남긴 기록이 환경 단서와 선택지에 스며드는 식으로.

한 줄 컨셉: **"시설은 배치를 이어 가며 수확한다 — 당신의 이야기가 다음 사람의 시설이 된다."**
스토리의 수확 전제(STORY.md §1)를 기능으로 문자 그대로 구현하는 것이다.

핵심 원칙 두 가지는 불변이다:
- **AI는 라이브로 맵을 만들지 않는다.** 변형은 전부 사전 제작 + 정답 테이프로 기계 증명.
  AI가 하는 일은 "문장 → 카테고리"(시뮬 이전)와 "기록 → 서사"(시뮬 바깥)뿐이다.
- **시뮬레이션에 닿는 모든 값은 시뮬 시작 전에 확정된다.** 레거시 데이터도 스테이지
  로드 전에 fetch가 끝나고, 그 뒤로는 100% 결정론이다.

## 1. 목표와 비목표

### 목표

1. **AI 활용이 플레이 안에서 보이게 한다.** 지금은 AI 활용 서사가 개발 프로세스(검증
   자동화)에만 있다. 이 기능으로 "플레이어의 언어가 게임을 바꾼다"가 런타임에 생긴다.
2. **선택이 세계를 바꾸는 체험.** 같은 게임을 두 번 하면 다른 맵·다른 결말이 나온다
   (리플레이 가치 — 심사위원이 옆 사람과 다른 결과를 받는다).
3. **플레이어 간 연결.** 내 결말이 다음 사람의 게임에 남는다 — 해커톤 부스에서
   "앞 사람이 남긴 것"을 뒷 사람이 발견하는 순간을 만든다.
4. 기존 강점(결정론·기계 증명·행사장 안정성)을 **하나도 깎지 않는다.**

### 비목표 (하지 않는 것)

| 하지 않는 것 | 이유 |
|---|---|
| AI의 라이브 맵 생성 | solvability 증명 불가. 사용자 결정으로 명시 배제됨 |
| AI의 틱 판정 개입 | 결정론 파괴. 상위 PRD §5와 동일 |
| 자유 문장의 원문을 **그대로** 다른 플레이어에게 노출 | 모더레이션 리스크. 반드시 GPT 재작성 + 검수 통과분만 (§3.5) |
| 선택에 따른 스테이지 **수** 증감 | 15스테이지 4막 구조와 par 곡선은 고정. 바뀌는 건 변형(내용물)뿐 |
| 실시간 멀티플레이 | 레거시는 비동기 흔적 공유이지 동시 접속이 아니다 |

## 2. 플레이어 경험 — 처음부터 끝까지 한 사람의 시나리오

> 기능 나열 전에, 한 플레이어(가칭 "배치 #48")가 겪는 흐름으로 전체를 보인다.

배치 #48이 게임을 시작한다. 1막 어딘가의 환경 단서(`E`)에 이런 인쇄체가 있다:
`전 배치 기록 — 회수 2. 특이사항: 대상이 문 앞에서 오래 머묾.` — **이건 배치 #47,
즉 직전에 플레이한 실제 사람의 기록을 GPT가 시설 문서 어투로 재작성한 것이다.**

1막이 끝나고 막간 만화. 마지막 컷에서 선택지가 뜬다 — 주인공의 혼잣말 두 갈래:
`...조용히 가자. 천천히.` / `...뛰어. 생각은 나중에.` 배치 #48은 후자를 고른다.
→ 2막의 지정 스테이지 두 곳이 **대담 축 변형**으로 로드된다(경비 배치와 지름길
구조가 은닉 축 변형과 다르다 — 둘 다 사전 제작·기계 증명된 맵이다).

3막 막간에서는 자유 입력이 나온다. 잔상들이 진열된 선반을 본 직후, 문장 하나를
쓰게 한다: `쟤들한테 하고 싶은 말이 있다면 —` 배치 #48은 "미안해, 꼭 데리러 올게"
라고 쓴다. GPT가 이 문장을 **관계 축: 동료(HIGH)** 로 분류하고, 원문은 결말용으로
보관한다. → 4막 지정 스테이지가 관계 축 변형으로 로드된다.

결말. 배치 #48의 DEBT는 2 — 기존 분기로는 "나왔지만 두고 왔다"다. GPT가 그의 선택
(대담·동료), 그의 문장("데리러 올게"), 플레이 로그(사망 5회, 잔상 11명, 3막에서
기침 1회)를 받아 **그 사람만의 결말 서사**를 쓴다. 마지막에 칭호가 찍힌다:
`데리러 오겠다고 말한 자 — 수율 2.`

그리고 배치 #48이 남긴 것 중 검수를 통과한 조각 — 칭호와 통계, 그리고 시설 어투로
재작성된 한 줄 — 이 서버에 적재된다. **배치 #49의 1막 환경 단서가 그것으로 바뀐다.**
어떤 선택지에는 이런 문구가 붙는다: `이전 배치의 71%가 여기서 두고 갔다.`

## 3. 기능 명세

### 3.1 막간 선택 시스템 (기반 — AI 없음)

- **위치**: 기존 막간 만화(`interlude.ts`) 4곳의 마지막 컷. 만화 시스템을 재사용하고
  선택 UI만 추가한다(키보드 `←/→` + `Enter`, 모바일 탭).
- **형식**: 주인공의 혼잣말 2갈래. STORY.md 규칙 전부 준수 — 명령조 금지, 키 이름
  금지, 호칭 사다리(막간 2의 선택지는 잔상을 `것들`로 부를 수 있다 — §7 예외 규정).
- **선택 축 2개로 환원한다** (조합 폭발 방지의 핵심):
  - **태도 축**: `은닉(STEALTH)` ↔ `대담(BOLD)` — 막간 1·3에서 갱신
  - **관계 축**: `도구(TOOL)` ↔ `동료(BOND)` — 막간 2·4에서 갱신
- 선택은 `Session`에 열거형으로 축적. 무입력 15초면 기본값(은닉·도구)으로 진행
  (부스에서 자리 비움 대비).

### 3.2 사전 제작 스테이지 변형 (사용자 확정 사항)

- **변형 대상**: 막당 1~2개, 총 **6개 스테이지**에 변형 2종씩(축 값에 따라 택1).
  나머지 9개는 단일판 유지. → 추가 맵 6장, 추가 정답 테이프 6개 + 잔상 0 불가 증명 6건.
  이 수량이면 기존 solvability 테스트 체계에 그대로 얹힌다.
- **변형의 원칙**: 변형끼리 **레이아웃 뼈대는 같고 장치·경비 구성이 다르다**
  (예: 은닉판은 grate 지름길 + WATCHER, 대담판은 넓은 홀 + BRUTE). 뼈대를 공유해야
  제작·검증 비용이 절반이 되고, 플레이어도 "선택이 바꿨다"를 알아본다.
- **선택 → 변형 매핑은 순수 함수다.** AI 개입 없음. 막간 종료 시점에 다음 막의 변형이
  확정되고, 그 뒤는 기존과 완전히 같은 결정론 시뮬이다.
- **초반 30초 안에 차이가 보이게 배치한다**: 변형 스테이지의 첫 화면(입구 방)에서
  이미 구성이 달라 보여야 한다. 선택의 결과가 늦게 회수되면 선택이 겉치레로 느껴진다
  (§9 페르소나 P2 리뷰 반영).

### 3.3 자유 문장 입력 → 카테고리 환원 (GPT 지점 ①)

- **위치**: 막간 3(필수 1곳)과 막간 4(선택 1곳). 전부 자유 입력으로 하지 않는 이유:
  타이핑은 부담이라 2곳이 상한이고, 무대 데모에서는 1곳이면 충분하다.
- **입력 UI**: 한 줄 텍스트(최대 60자). **건너뛰기 = 선택형 폴백** 항상 제공
  (모바일·타이핑 기피 대응 — §9 P3 반영).
- **파싱 계약**: GPT 호출은 OpenAI **Structured Outputs**(JSON 스키마 강제)로 받는다.
  스키마: `{ attitude: STEALTH|BOLD|NEUTRAL, bond: TOOL|BOND|NEUTRAL,
  intensity: 1..3, flavorTag: enum(12종), unsafe: boolean }`.
  `NEUTRAL`이면 해당 축 미변경. `unsafe=true`(욕설·현실 인물 등)면 축 미변경 + 원문을
  결말·레거시에 **쓰지 않는다**(입력 자체는 조용히 수용 — 플레이어를 혼내지 않는다).
- **어떤 문장이 와도 도착지는 유한하다**: 축 2 × 강도 3 × 태그 12가 전부다. "예상 답변을
  주르륵 만들어 미리 매핑한다"는 사용자 방향을 스키마로 구현하는 것이며, 미리 만든
  변형·연출의 범위를 절대 벗어나지 않는다.
- **오프라인 폴백**: 로컬 키워드 사전으로 축·강도만 추출(태그 생략). 데모 리허설 때
  예상 문장 30개를 캐시에 적재한다.

### 3.4 개인화 결말 생성 (GPT 지점 ②)

- **입력**: 선택 축 최종값, 자유 문장 원문(안전 판정 통과분), 플레이 로그(사망
  횟수·원인·잔상 수·DEBT·소음 사용·클리어 시간 — 전부 시뮬에 이미 있는 데이터).
- **출력**: 2~3문단 결말 서사 + 칭호 1줄. **엔딩의 정체는 성향 축적 매트릭스(DEBT 3단
  × 관계 성향 3단 + 「새벽」 = 10종, [`STORY-BRANCH.md`](./STORY-BRANCH.md) §3)가
  순수 함수로 정하고**, GPT는 정해진 엔딩 안을 개인화한다 — 분기 자체를 GPT가 정하면
  STORY.md의 엔딩 설계가 무너지기 때문이다. GPT가 서사를 쓰는 엔딩은 E10·E3 두 종뿐,
  나머지 8종은 변주 슬롯이 있는 고정 텍스트라 오프라인에서도 10종 전부 나온다.
- **세계관 가드**: 시스템 프롬프트에 STORY.md의 사실 요약 + 금지 목록(폭력·고문 묘사
  금지, 악당 연설 금지, 사무적 어투, 진실을 대사로 정리하지 않기)을 넣는다.
  출력 검증: 금지 패턴 필터 + 길이 클램프. 실패 시 **템플릿 결말(현행)로 폴백** —
  결말이 안 나오는 경로는 없다.
- **엔딩 카드**: 칭호 + 통계 + 서사 첫 문장을 한 화면으로. 부스에서 옆 사람과 비교하는
  용도(공유 이미지 저장은 후순위).

### 3.5 레거시 — 「다음 배치」 (사용자 확정: C 최대 강화)

내 결말이 다음 플레이어의 세계에 남는다. **남는 것은 세 종류이고, 전부 시뮬 시작 전에
로드되는 텍스트/열거형 데이터다** — 맵 지오메트리는 절대 아니다.

| 남는 것 | 다음 플레이어가 겪는 방식 | 시뮬 영향 |
|---|---|---|
| **기록 조각** — 이전 배치의 칭호·통계를 GPT가 시설 문서 어투로 재작성한 1줄 | 환경 단서(`E`) 일부가 이 조각으로 교체된다. `전 배치 기록 — ...` | 없음 (텍스트만) |
| **선택 통계** — 역대 선택 비율 | 선택지 옆에 인쇄체 1줄: `이전 배치의 71%가 여기서 두고 갔다.` | 없음 (표시만) |
| **기본 변형 편향** — 직전 배치의 최종 축 값 | 무입력 15초 기본값이 직전 배치의 선택을 따른다 — "앞 사람의 관성이 시설에 남아 있다" | 있음 — 단, 사전 제작 변형 중 택1이라는 사실은 불변 |

- **저장소**: 서버리스 함수 1개 + KV 저장소(레거시 조각 최근 N개 + 축 통계 카운터).
  기존 계획의 API 프록시와 같은 함수에 얹는다 — 인프라 신규 항목은 0개다.
- **모더레이션 파이프라인**: 다른 사람에게 보이는 텍스트는 **원문이 아니라 GPT 재작성문**
  이고, 재작성 전에 OpenAI Moderation API를 통과해야 하며, 실패분은 통계에만 반영하고
  텍스트는 버린다. 즉 타인의 자유 문장이 원문 그대로 화면에 뜨는 경로가 없다.
- **오프라인 폴백**: 우리가 만든 시드 레거시 20개를 번들에 포함. 네트워크가 없으면
  시드에서 뽑는다 — 첫 플레이어와 오프라인 데모에서도 "이전 배치"는 항상 존재한다.
- **결정론 보증**: 레거시 fetch는 스테이지 로드 **전**에 완료·고정된다. 같은 레거시
  스냅숏 + 같은 테이프 = 같은 결과. fetch 지연 시 시드로 즉시 대체(로딩 대기 없음).

## 4. 아키텍처 제약 — 기존 증명을 지키는 선

기존 게임의 세 주장이 이 기능 이후에도 참이어야 한다. 각 주장별로 지키는 방법:

1. **"전 스테이지 클리어 가능 + 혼자서는 불가"** → 변형 6장 각각에 정답 테이프와
   단독 공략 실패 증명을 추가한다. 변형 포함 총 21장(15+6)이 전부 테스트에 오른다.
2. **"재생 오차 정확히 0"** → GPT·레거시·선택은 전부 시뮬 밖 레이어(`Session`/막간)에
   산다. `SimState`에 새로 들어가는 것은 "이번 스테이지가 어느 변형인가"라는 열거형
   하나뿐이고, 그것은 시뮬 시작 전에 확정된다.
3. **"런타임 네트워크 호출 0"** → **이 주장은 이 기능으로 깨진다.** 숨기지 않고 문구를
   바꾼다: "게임 판정에는 네트워크가 관여하지 않는다. 네트워크는 이야기(파싱·결말·
   레거시)에만 쓰이고, 끊겨도 게임은 시드 데이터로 완주된다." README·PITCH의 해당
   문구 수정을 이 기능의 완료 조건에 포함한다(§9 P4 리뷰 반영).

개인정보: 마이크 주장(오디오 저장·전송 0)은 그대로 참이다. 새로 수집하는 것은
플레이어가 직접 쓴 문장과 플레이 통계뿐이며, 입력 UI에 "이 문장은 다음 플레이어에게
각색되어 보일 수 있다"를 한 줄로 고지한다.

## 5. 범위 사다리 — 어디서 잘려도 출시 가능하게

| 단계 | 내용 | AI | 잘렸을 때 남는 것 |
|---|---|---|---|
| L1 | 막간 선택 2축 + 결말 분기 플래그 | 없음 | 선택 있는 스토리 게임 |
| L2 | 변형 6장 사전 제작 + 테이프 증명 | 없음 | 선택이 맵을 바꾸는 게임 |
| L3 | 자유 문장 파싱(Structured Outputs) + 폴백 | ① | "내 문장이 세계를 바꾼다" |
| L4 | 개인화 결말 + 엔딩 카드 | ② | "내 문장이 결말이 된다" |
| L5 | 레거시(기록 조각·통계·편향) + 모더레이션 | ③ | "내 결말이 다음 사람에게 남는다" |

L1→L5 순서로만 쌓는다. **L2까지는 AI가 없어도 게임을 좋게 만드는 투자**라 손해가
없고, L3부터가 AI 킥이며, L5가 이 안의 차별화 정점이다. 발표 대본은 도달한 단계까지만
쓴다(미도달 단계 언급 금지 — PITCH.md 원칙).

기존 확정안이던 **AI 아이템 대장간은 L5 완료 후 보너스로 강등**한다. 사유: 이 안의
L3~L5가 대장간의 심사 가치(자연어 → 게임 반영)를 흡수하면서 서사 통합은 더 깊다.
둘 다 하기엔 변형 6장 제작·증명이 만만치 않다.

## 8. 가정한 심사 기준 (공식 기준 공개 전)

OpenAI 주최 게임 해커톤이라는 사실에서 합리적으로 가정한다. 공개되면 이 표만 갈아끼운다.

| 기준(가정) | 우리 해석 |
|---|---|
| **OpenAI API 활용의 깊이** | 호출 여부가 아니라 "API라서 가능한 설계"인가 — Structured Outputs로 자유 언어를 게임 상태로 안전 환원, Moderation으로 UGC 파이프라인 |
| **창의성/독창성** | 다른 팀이 못 베끼는가 — 결정론 게임에 UGC 서사를 얹으면서 증명을 유지하는 구조 |
| **게임성/재미** | AI를 빼도 게임인가 — L1·L2가 그 답 |
| **기술 완성도** | 무대에서 안 죽는가, 주장에 근거가 있는가 — 테스트·폴백 체계 |
| **발표/데모** | 3분 안에 전달되는가 — 자유 문장 1회 + 결말 회수 + "앞 심사위원의 흔적" 발견 장면 |

## 9. 심사위원 페르소나 리뷰 → 반영

네 명의 가상 심사위원을 세우고, 이 문서 v1을 그들의 눈으로 검토해 **문제를 찾고,
반영해서 v2(현재 문서)를 만들었다.** 각 항목: 페르소나 → 지적 → 반영 위치.

### P1 — OpenAI DX 엔지니어 (API 활용 깊이를 본다)

> "GPT를 '문장 분류기'로만 쓰면 API 활용 점수는 평범합니다. 분류는 작은 모델도 합니다.
> OpenAI 스택이라서 가능한 게 뭔지 보여 주세요. 그리고 UGC를 받으면서 모더레이션
> 얘기가 없으면 저는 바로 물어봅니다."

**반영**: 파싱을 Structured Outputs 계약으로 명시(§3.3), 레거시 파이프라인에 Moderation
API를 필수 단계로 편입(§3.5). 결말 생성 프롬프트에 세계관 가드를 넣는 설계(§3.4)도
"프롬프트 엔지니어링이 아니라 시스템 설계"로 발표에서 말할 수 있게 문서화했다.

### P2 — 게임 디자이너 (선택의 무게를 본다)

> "선택 게임의 함정은 '선택했는데 아무것도 안 변하는 느낌'입니다. 변형이 스테이지
> 깊숙한 곳에서만 다르면 플레이어는 차이를 모릅니다. 그리고 결말에서만 회수되는
> 선택은 해커톤 데모에선 죽은 기능입니다 — 심사위원은 결말까지 안 갑니다."

**반영**: 변형의 차이를 입구 방에서 보이게 하는 배치 원칙(§3.2), 선택 통계 문구
(`이전 배치의 71%...`)로 선택 순간 자체에 무게 추가(§3.5), 데모 루트에 "자유 문장
1회 + 다음 스테이지에서 즉시 변형 확인" 장면을 배정(§8 발표 행).

### P3 — 프로덕트/UX 심사위원 (마찰을 본다)

> "게임 중간에 타이핑을 시키는 순간 이탈이 생깁니다. 모바일에선 더요. 그리고
> 무입력으로 방치되면 어떻게 되죠? 부스 환경에선 자리 비움이 흔합니다."

**반영**: 자유 입력은 최대 2곳 + 항상 건너뛰기(선택형 폴백) 제공(§3.3), 무입력 15초
기본값 진행(§3.1), 입력 60자 제한. 분류 결과를 화면에 직접 노출하지 않는 것(§6)도
"오분류가 마찰이 되는 순간"을 없애기 위함이다.

### P4 — 회의적인 엔지니어 (주장의 구멍을 본다)

> "README에 '네트워크 호출 0'이라고 써 놨던데, 이 기능 들어가면 거짓말이 되네요.
> 심사 때 그거 걸리면 다른 주장까지 의심받습니다. 레거시가 시뮬에 영향을 주면
> 결정론 주장은요? 첫 플레이어는 레거시가 없을 텐데요?"

**반영**: "네트워크 0" 문구 수정을 완료 조건에 포함(§4-3), 레거시의 시뮬 영향을
"사전 제작 변형 중 택1의 편향"으로만 한정하고 fetch를 시뮬 시작 전에 고정(§3.5),
시드 레거시 20개로 첫 플레이어·오프라인 문제 해소(§3.5). 문서 전체에서 "깨지는
기존 주장"을 숨기지 않고 §4에 명시했다.

## 10. v1 → v2에서 바뀐 결정 요약

1. 자유 입력 전면 확대 → **2곳 상한 + 건너뛰기 필수** (P3)
2. 파싱 방식 미정 → **Structured Outputs 스키마 계약 + NEUTRAL 안전값** (P1)
3. 레거시 원문 공유 검토 → **원문 비노출, GPT 재작성문 + Moderation 통과분만** (P1)
4. 변형 차이 위치 자유 → **입구 방에서 보이게 강제** (P2)
5. "네트워크 0" 주장 방치 → **문구 수정이 완료 조건** (P4)
6. 대장간 병행 → **L5 이후 보너스로 강등** (제작 비용 현실화)
