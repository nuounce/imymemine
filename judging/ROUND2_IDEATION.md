# 결과물 1. 한 페이지 결론

**가장 강한 경쟁력** [실측]
"경비가 과거의 나에게 실제로 반응한다"가 마케팅 문구가 아니라 **회의적 심사자의 통제 실험으로도 반증에 실패한 사실**이라는 것. 그리고 그 주장을 떠받치는 기계 증명 파이프라인(결정론 300세트·solvability 이중 증명·CI 게이트). 이 게임의 무기는 "재밌어 보인다"가 아니라 "주장한 것이 전부 검증된다"이다.

**우승을 막는 3대 위험**
1. **Codex 증거 공백** [실측] — 커밋된 저장소에 Codex 흔적 0건, 유일한 AI 귀속은 Claude 트레일러. 현 상태 제출 = "허위·과장" 실격 리스크. 유일한 해소: 행사 기간 실제 Codex 작업 + 범위 고지.
2. **발표 실물 부재** [실측] — 썸네일·영상·확정 대본·리허설 전부 없음. 게임이 4점대여도 Presentation이 2점대로 끌어내림.
3. **분기 야심의 범위 초과** [추론] — L5 풀셋(변형 6장+레거시 서버+엔딩 10종+자유입력 2곳)은 변형 증명 비용(장당 0.5~1일)과 QA 조합을 감안하면 잔여 기간에 완성도가 흩어질 위험. "야심의 80%를 버려야 20%가 심사장에서 산다."

**반드시 지킬 핵심 정체성**
① 판정에 네트워크·AI가 관여하지 않는 정수 결정론 ② 모든 스테이지의 기계 증명(증명 없는 콘텐츠는 출시하지 않는다) ③ "실패가 자원이 된다"(잔상·시체·DEBT) ④ 커밋된 근거 없는 주장은 하지 않는 정직성.

**추천 제품 방향**: **균형안** (결과물 3) — 버그·실물·Codex 증거를 P0로 깔고, 분기는 L3까지(+엔딩 10종 판정 함수), 변형은 6→4장 축소, 아이템 1~2종만. 레거시 서버(L5)는 본선 진출 후로.

**대표 Codex 활용 서사**: "우리는 Codex에게 코드가 아니라 **증명과 심사**를 시켰다" — ① 검증 파이프라인(결정론·solvability·QA 회귀) ② 루브릭 기반 자가 심사 루프(발견→수정→재심사). ⚠ 단, 이 서사가 성립하려면 **행사 기간에 같은 루프를 실제 Codex로 재실행하고 기록을 남겨야 한다**(현재까지의 루프 수행 도구는 Claude — 결과물 5).

**이번 기간에 하지 말 것**: 런타임 맵 생성(팀 PRD도 배제) / AI 아이템 대장간(PRD 스스로 강등) / 완전 트리 분기 / 리더보드 서버 / 15스테이지 순서 개편 / 증명 없는 보스 투입 / 자유입력 3곳 이상 확대.

# 분석 2. Codex 활용 전략 비교 (A/B/C)

## 전략 A — Codex 기반 개발·평가 루프

- **개발 가치** [실측]: 이 루프의 가치는 이미 증명됨 — 루브릭 기반 자가 심사가 held-pointer wipe·입력 드랍·발판 무경고를 실제로 찾았고, 발견→수정→재검증이 커밋·테스트로 남는 구조다. 검증 파이프라인(결정론 300세트, 정답 테이프 21장 예정)은 사람 수작업으로는 범위 자체가 불가능 — "Codex가 없었다면"의 답이 정량으로 나온다: 스테이지당 무작위 20세트 × 2회 재생 해시 대조를 매 커밋마다 사람이 할 수 없다.
- **점수 연결**: Codex Collaboration 하위 5기준(신뢰성·실질성·반복 루프·인간 결정·재현성)에 전부 직결. 특히 "반복 개선 루프 기록"은 Round 1에서도 수상권 평가.
- **발표 설득력**: "Codex가 심사위원 역할로 게임을 플레이하고 루브릭 점수를 매겼으며, 그 백로그를 사람이 취사선택해 고쳤고, 재심사에서 점수가 실제로 올랐다" — 저장소의 judging/ 폴더가 그대로 증거물.
- **필요 증거**: 행사 기간의 Codex 세션 기록, 루프 산출물(Round N 리포트), 수정 커밋, 재실측.
- **인간의 결정**: 백로그 취사선택(예: "진행 저장 없음은 의도"라며 Codex 권고를 기각한 기록 — 오히려 최고의 증거), 톤 결정 3포인트, par 설계.
- **과장 리스크와 진실 조건** ⚠: **지금까지 이 루프를 수행한 도구는 Claude다(커밋 트레일러가 증거).** 이 서사를 쓰려면 행사 기간에 동일 루프를 Codex로 실제 재실행해야 하며, 과거 수행분을 Codex 실적으로 표현하는 순간 실격 사유가 된다. 발표 문구: "행사 전 우리는 이 검증 문화를 만들었고, 행사 기간에는 Codex가 그 루프의 운전자였다"(양쪽 다 사실이 되도록 실행).
- **실브라우저 플레이 검증의 차별점**: 헤드리스 시뮬 증명(풀린다)과 실브라우저 에이전트 플레이(사람처럼 막힌다)는 다른 층위다 — Round 1의 블라인드 플레이가 시뮬 테스트가 못 잡는 것(입력 드랍·판정 피드백)을 잡았다는 사실 자체가 발표 소재.

## 전략 B — 플레이어 선택 기반 Codex 생성 결말

팀 PRD-AI-STORY가 이미 이 전략의 정답에 가깝게 설계돼 있다 [실측·문서]: 분기 정체는 순수 함수(GPT가 엔딩 번호를 정하지 않음), GPT 서사는 E10·E3 두 곳뿐, 나머지 8종 오프라인 완결, Structured Outputs+NEUTRAL 안전값, 모더레이션, 템플릿 폴백.
- **메커니즘 연결**: 상(DEBT=행동) × 열(관계=마음) × 말(자유 입력)이 기존 시스템(DEBT·Q·클리어 기록)을 그대로 저울로 씀 — 겉도는 생성형이 아니라 축적의 개인화. E10 "플레이어 문장 원문 인용" 규칙이 백미.
- **리스크**: ① 지연·실패 → 폴백 설계돼 있음(추가 요구: 폴백 발동을 데모에서 오히려 시연 가능하게) ② 세계관 이탈 → 가드+필터+폴백 ③ **"네트워크 0" 정체성 수정** — PRD가 정직하게 문구 교체를 완료 조건으로 삼았으나, 이는 Round 1 최강 무기("동시 100명에도 안 죽는다")의 재정의다. 문구 전략: "**판정에는** 네트워크 0 — 끊겨도 엔딩 10종 전부 나온다"를 전면에.
- **데모 안정성**: 자유입력 1회+캐시 리허설 30문장이면 무대 리스크 통제 가능. 단 E10 시연은 막간 4 직전 세이브 필요(STORY-BRANCH 미결 3) — 없으면 무대에서 못 보여준다.
- **분담 판정** [제안]: 사전 작성(엔딩 골격 10종·변형 텍스트) = 사람+빌드타임 생성·검수 / 런타임 = 파싱(L3)·E10 에필로그(L4)만. L5 레거시(서버)는 본선 후.

## 전략 C — Codex 분기·퍼즐 생성 + 자동 검증

- **평가**: 런타임 생성은 팀 PRD가 이미 배제(옳음 — solvability 증명 불가). 남는 유효 형태는 **빌드타임**: "Codex가 변형 후보(장치·경비 재배치)를 N개 제안 → 사람이 선별 → 솔버·테이프로 기계 증명 → 커밋". 이건 사실상 전략 A의 콘텐츠 응용이며, 변형 4~6장 제작 자체를 Codex 작업으로 수행하면 **A의 증거와 L2 콘텐츠를 동시에 얻는다.**
- **비용** [실측 기반]: 변형 1장 = 뼈대 공유 시 제작 0.5일 + 테이프 증명 0.5~1일. 6장 = 6~9일(1인) → **4장 축소 권고**.
- **자동 검증 실패 시**: 증명 실패한 변형은 폐기(출시 안 함) — "증명 없는 콘텐츠 없음" 원칙 유지가 곧 발표 문구.

## 비교표

## 3.1 분기 구조 7종 비교 결과

**종합 판정** [추론]: 팀 현 기획 = **④ 몸통 + ② 합류 규율 + ⑦ 결말 레이어의 3중 혼합형**이며 합리적이다. 근거: (1) 변형 선택이 축 값의 순수 함수 + 스테이지 간 교차항 없음 → **조합 폭발 구조적으로 0, QA가 "21장 × 기존 파이프라인"으로 선형** (2) ④의 약점(안 보임)은 입구 방 차이+⑦의 텍스트 변주가, ⑦의 약점(체감 없음)은 ④가 상호 보완 (3) 진행 저장 없음 방침과 정합(세션이 드는 것 = 정수 2+열거형).

**보완점 3** [제안]: ① 1막 무변형 → 막간 1 선택의 회수가 2막까지 지연되므로 1막 말미에 텍스트·단서 수준 경량 변주 추가 검토 ② 텔레메트리 ±1의 막당 상한 명문화(STORY-BRANCH 미결 2 — 사후 축 뒤집힘 방지) ③ **변형 쌍 난이도 등가 증명 부재** — 은닉판/대담판 관용폭 격차 상한을 qa.test에 추가하지 않으면 선택이 난이도 함정으로 오독됨.

# 결과물 5. Codex 증거 패키지 (구체 목록)

**전제 정직성 [중요]**: 행사 전 개발에 Claude(Claude Code)가 깊게 개입했고 커밋 트레일러가 그 증거다. 이것을 숨기는 것이 아니라 **범위 고지로 해결**한다 — 약관은 기존 프로젝트 활용을 허용하며 범위 구분을 요구할 뿐이다. "행사 전: 팀+AI 보조로 기반 제작 / 행사 기간: Codex가 아래 작업 수행"이 성립하면 실격 리스크는 사라진다. 타 도구 사용 금지 조항 여부는 약관 재확인 필요(결과물 6 질문).

남길 것:
1. **SCOPE.md** — 행사 전 범위(커밋 해시 구간) vs 행사 기간 신규(커밋 구간), 한 페이지
2. **행사 기간 Codex 세션 기록** — 계획→실행→검증 로그 보존(스크린샷+로그 파일), 커밋 메시지에 세션 참조
3. **루브릭 평가 루프 Round 2를 Codex로**: judging/ 폴더에 ROUND2 리포트 — 발견→수정 커밋→재실측 사슬
4. **수정 전후 플레이 영상** (held-pointer wipe 등 재현 2건은 이미 재현 절차 보유)
5. **실패 재현 시드·테이프** — 결정론이라 버그 재현이 테이프 첨부로 끝남 (타 팀이 못 하는 증거 형식)
6. **테스트 수 실측 스냅샷** — 커밋별 증가 곡선(159→364→…) 그래프 1장
7. **Codex 제안 기각 사례** — 최소 2건 기록 (예: "진행 저장 추가" 권고 vs 팀의 일회성 결정, Q 페널티 등) — 인간 결정 증빙의 핵심
8. **README에 Codex 절 신설** + 커밋 트레일러 규칙 변경(행사 기간 커밋에 도구 명시)
9. **런타임 AI 범위 선언문** — "판정 네트워크 0 / 이야기 레이어만 API / 전 기능 오프라인 폴백" 한 장
10. **라이브 데모 재현 경로** — 무대에서 Codex 세션 1개를 열어 실시간으로 백로그 1건을 수정·테스트 통과시키는 30초 시연(리허설 필수) 또는 그 녹화
